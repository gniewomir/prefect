# Host root login via IHP; no Stack-managed account SSH key

DigitalOcean account SSH keys are unique by public-key fingerprint, not resource name, so per-Environment `digitalocean_ssh_key` names still collide when Environments share one pubkey under one account. That object is also account-scoped and multi-Environment — neither a Durable nor a Recreatable under ADR-0025. Propraetor therefore does **not** manage provider-account SSH keys in the Stack. **Initial Host Provisioning** installs the operator’s public key for **root** Host login only (not the Platform User). Operator-machine inputs are **Operator Configuration** (today: matched public- and private-key paths); provider API auth remains **Provider Credential** (`DIGITALOCEAN_TOKEN`). Both may be baselined from repo-root `.env` ([ADR-0038](0038-repo-root-operator-dotenv.md)). Apply reads the public path and passes pubkey content into the Stack as `host_root_ssh_public_key` for the IHP template. Operator Configuration is required only where something consumes it (Apply / SSH surfaces per need); Park and Teardown need Provider Credential only. Host-session `operator` and `verify` profiles stay as behavior modes; both use the Operator Configuration private path. Clean break (ADR-0018): drop `TF_VAR_DIGITALOCEAN_PUBLIC_KEY`, `SSH_IDENTITY`, and `VERIFY_SSH_IDENTITY`. Existing Stack-managed account keys may be destroyed with the resource. Amends ADR-0019 (SSH key is not an Environment account-unique Stack name).

## Considered

Ignore-422 / dual State ownership of one account key; Terraform data-source or API ensure of a shared account key; per-Environment generated keypairs as the default; ssh-agent-only / optional private path; authorizing the Platform User for operator SSH. Rejected — wrong lifecycle class, surprising multi-Environment ownership, or unnecessary surface for the solo-operator default.
