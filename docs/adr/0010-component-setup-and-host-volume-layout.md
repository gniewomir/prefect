# Component Setup, ensure-components, and Host Volume layout

Public Hosts still get Components (Service Network, then Edge) only **after** Initial Host Provisioning: IHP remains a carrier (engine, Prefect User, port floor, Host Volume mount) and does not run Component Setup or install Workloads — putting Setup inside cloud-init was rejected because SSH/copy is unsafe mid-IHP and user_data churn would recreate the Host for every Component change. Instead, operator-side `prefect/ensure-components.sh` waits for IHP, scp/tar-copies each Component tree onto the Host Volume as root, chowns to the Prefect User, and runs each Component’s idempotent `setup.sh` in a hardcoded order (`network`, then `edge`). Success means the Component **is in the correct state** (header contract on every Component Setup script). Workload Setup is a separate term and path (including Route registration); it is not invoked by ensuring Components.

**Host Volume layout:** mount root `/var/lib/prefect` stays root-owned; everything under it is Prefect User–owned. **Source** (repo mirror, scp-replaced): `/var/lib/prefect/components/{network,edge}/` — includes Edge `nginx.conf` (container bind-mounts it from here); no `certs/` in the source tree. **Data** (Host/Workload durable bytes): `/var/lib/prefect/components_data/edge/{routes,certs}/`. Component Setup ensures the empty-routes stub into data `routes/` and never deletes other Route files; Quadlet units stay under the Prefect User’s home. Durable source on the volume lets Component Setup re-run after Host rebuild without relying on IHP; Destroy still removes the volume with the Stack.

**Rejected:** Setup inside IHP; rsync; operator script named apply/provision (Stack apply / IHP collision); root-owned `components/` (blocks rootless binds); certs under the source mirror; wiping runtime routes on ensure; treating Workloads as Components.
