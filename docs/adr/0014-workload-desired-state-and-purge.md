# Workload Intent modes and Purge

The Workload Manifest carries a **Workload Intent** (naming: ADR-0017; thin Manifest + authored Quadlets: ADR-0024): **run**, **stop**, or **trash**. **run** — operator-authored Quadlets up; operator-authored Routes installed when present; HTTP semantics are whatever installed Routes declare. **stop** — those Quadlets stopped; that Workload’s installed Routes removed (Edge default miss, not a Prefect 503); Workload data and Domain-scoped certificates preserved. **trash** — installed Routes removed; Workload data retained until **Purge**, which permanently deletes every Workload whose Intent is **trash** and Workload-associated data (installed Routes, Host Volume Workload tree including `routes/` / `quadlets/` SoT, unit files named in that SoT, that Workload’s Platform User EnvironmentFile tree under `~/.config/platform/workloads/<basename>/`, and Setup-owned Environment Configuration drop-ins for its `quadlets/*.container` units — ADR-0035) — not Domains or Domain-scoped certificates (ADR-0022). Purge never touches Workloads whose Intent is **run** or **stop**. ACME want-list is Domain assignment (ADR-0023), not Manifest claims — Setup and Purge do not rebuild it.

**Intent stop uninstalls Routes (no Prefect 503):** process lifecycle parks without Prefect-owned Edge HTTP shells (Edge default miss — ADR-0022); Domain/certs stay.

**Intent trash + Purge over immediate delete on Manifest edit:** makes removal explicit and batchable.
