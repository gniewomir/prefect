# Placeholder PEMs are create-if-missing for Domain fronts

Domain fronts reference stable cert paths (`components_data/edge/certs/<fqdn>/{fullchain,privkey}.pem`) and nginx will not load a TLS server if those files are missing, while Setup still does not require usable ACME PEMs (ADR-0012 / ADR-0015 — oneshot soft-fails CA; Edge Setup waits only for oneshot completion / front-door reload). ensure-components therefore plants **self-signed placeholder** PEMs for each want-list FQDN **create-if-missing only** (both files present → never touch; either missing → write a fresh pair), **before** Domain-front install / Edge reload that would pick up that front. Placeholders use CN+SAN = that FQDN; ensure-components does not validate or heal complete-but-corrupt pairs. ACME later replaces PEM bytes in place and never mutates Domain fronts (ADR-0028). Names leaving the want-list are not pruned (ADR-0023). Acceptance distinguishes placeholders from Let’s Encrypt staging by verifying against the official staging root bundle (#70) — no Prefect marker files. Delaying Domain fronts until after ACME, or omitting `ssl_*` until issuance, was rejected: it fights stable drop-ins and soft-fail ACME Setup.

**Builds on:** ADR-0010 (certs layout), ADR-0012 / ADR-0015 / ADR-0023 (Edge ACME soft-fail + Domain want-list; Setup waits for oneshot settle), ADR-0028 (Domain fronts pin cert paths).
