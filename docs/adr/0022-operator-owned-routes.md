# Operator-owned Routes; Setup gathers, Manifest does not project

HTTP reachability for Workloads is operator-owned: Route content is native config under `workloads/<name>/routes/` (source of truth). Workload Setup installs those files into the Edge routes directory as `<name>--<filename>` when Intent is **run**, removes that Workload’s installed Routes on **stop** / **trash**, and reloads the Edge — it does not generate shells, proxy bodies, or Manifest **interior** splicing. Edge keeps sole :80/:443, ACME, and :80 HTTP-01 + redirect; ACME must not reproject Routes after issue/renew. Domain owns names and certificate material; ACME want-list is Domain assignment (ADR-0023); Purge deletes Workload tree, installed Routes, and units — not Domains or certs. Clean break (ADR-0018): glossary, Setup, tests, and related ADRs move together; no dual-read of Manifest Route projection.

**Considered:** Operator edits `edge/routes/` directly with no Workload-tree SoT (tribal ownership, weak Purge/stop reconcile); keep Manifest-projected shells + optional interior (Prefect owns vhost behaviour); fold ACME want-list cutover into the same delivery as reachability (omnibus with #44). Rejected for the reachability cutover; want-list SoT is ADR-0023 / #44.

**Supersedes (projection / Intent-HTTP slices):** ADR-0011 (Manifest produces Routes); ADR-0012 (Setup/ACME project TLS shells); ADR-0014 Intent **stop** 503 / name-hold-as-reachability; ADR-0015 post-issue Route reprojection. ADR-0007 / ADR-0013 keep Edge + Service Network + :80 ACME/redirect / empty-Edge 404; drop Intent-aware proxy/503 prose when those ADRs are rewritten with behaviour.
